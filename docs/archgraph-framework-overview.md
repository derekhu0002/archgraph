# ArchGraph 总纲

> 本文是「ArchGraph 框架介绍系列」的总纲与导读。它不展开每个子话题的细节，而是先给出一个统一的认知模型：**ArchGraph 用一张意图架构图，把 Agent 工程中原本割裂的两条线——架构（系统由什么构成、谁负责什么）与 AI（Agent 如何记忆、如何检索、如何协作）——收拢进同一个模型。**

---

## 一、一句话

**ArchGraph 是一个架构图驱动的 Agentic Engineering 框架：以一张 ArchiMate 3.2 建模的意图架构图为单一事实源，让 Agent 的设计、执行、记忆与治理都围绕同一份可执行、可追溯的图展开。**

它同时是：

- 一门**统一的建模语言**——把 Harness 设计与目标产品设计放进同一个模型；
- 一套**工程约束**——定位先行、验收先行、变更可证、写入无损；
- 一层**Agent 的长期记忆**——图谱驱动的记忆与检索，通过单一 MCP 接口读写。

---

## 二、为什么需要一张图

Agent 已经能写代码、能调研、能发布内容。但真正把它当作**工程**来交付时，缺口不在"模型够不够强"，而在四个结构性问题：

1. **意图漂移**——长任务中 Agent 逐步偏离最初目标，人很难察觉；
2. **黑盒执行**——它读了什么、遵循了什么规则、为什么这么改，缺乏可观测性；
3. **验收靠感觉**——交付物"看起来对"，却缺少可执行、可回归的验收标准；
4. **经验无法沉淀**——技能与规则散落各处，每次开工近乎从零开始。

这四个问题的共同点是：**缺少一份人和 Agent 都能读懂、且能被机器执行的"施工图"。** 换更强的模型解决不了它们，因为它们不是智力问题，而是**结构与治理**问题。

ArchGraph 的出发点因此很朴素：**Agent 缺的不是更聪明的脑子，而是一张施工图。**

---

## 三、心智模型：意图架构图是单一事实源

ArchGraph 的中心是一份 **意图架构图谱（Intent Architecture Graph）**，文件形态是 `design/KG/SystemArchitecture.json`，用企业架构标准 **ArchiMate 3.2** 建模。

三个关键性质，决定了它为什么能当"单一事实源"：

- **结构化**：图中的每个元素都有类型（Business Actor、Business Role、Work Package、Skill、Application Component……），元素之间是**带类型、可校验**的关系（Assignment、Triggering、Association……），而不是自由文本。
- **可视化**：同一张图可以从不同 **Viewpoint（视角）** 切成不同 **View（视图）**。产品经理看 Application Cooperation，工程师看 Implementation and Migration，看到的是同一份数据的不同切面。
- **可执行**：元素上挂载**可执行的验收用例**与 **Skill/Rule**，提交记录回写到元素。图不只是"画出来"的，它能驱动真实工作。

于是，"我们想交付什么"与"Agent 该怎么被约束着交付"第一次写在**同一张纸**上。目标对齐不再依赖开会，而是**结构性的**。

---

## 四、两条主线

ArchGraph 的内容体系可以拆成两条线。理解这两条线，就理解了整个框架。

### 主线 A：架构线——设计"工人"和"房子"

这条线回答：**系统由什么构成？谁负责什么？如何协作？**

- **AML（Agent Modeling Language）**：我们没有另造 DSL，而是把 ArchiMate 3.2 扩展为 Agent 建模语言——只新增 `Skill` 与 `Rule` 两个元素（标准里确实没有），其余概念尽量映射到标准元素。关系合法性由一张关系推导矩阵约束，非法连接在**建模阶段**就被拦下，而不是等到运行时。
- **统一模型**：产品侧用 Application Component / Application Function，Agent 侧用 Business Actor / Business Role / Skill / Rule，两者通过 **Work Package** 连接——一个工作包同时指向产品组件与 Agent 技能，成为"目标 ↔ 执行者"的枢纽。
- **视图与视角**：同一份图，人看全局与职责，Agent 看任务相关的局部子图。视图不是截图，而是**带成员约束的投影**。

> 这一线将在后续篇章《AML：把 ArchiMate 3.2 扩成 Agent 建模语言》《统一模型：产品与 Harness 同图》中展开。

### 主线 B：AI 线——图谱即记忆

这条线回答：**Agent 如何记住、如何检索、如何在图上演化？**

- **图谱即记忆**：长期记忆直接挂在 Business Actor 的子视图层级上，分三层——T1 工作记忆（会话摘要）、T2 长期记忆（可语义召回）、T3 档案（归档）。会话启动时，WakeupGuideline 先恢复 T1 摘要，Agent 不会"忘记上次做到哪儿"。
- **GraphRAG 检索**：`SystemArchitecture.json` 是权威源，Neo4j 是其**从属投影**（JSON 改，Neo4j 跟着同步，不是反过来）。检索不是单纯的向量相似度，而是"语义种子 + 语义闭包 + 结构化补全"的组合。
- **检索的双通道**：语义检索（`getSystemArchitecture` / `memory_search`）负责"按意思找"，只读 Cypher（`queryNeo4jGraph`）负责"按结构找"。两者分工明确，前者优先。

> 这一线将在后续篇章《图谱即记忆：三层记忆与上下文组装》《检索深潜：GraphRAG + 混合检索 + 重排》《双通道检索》中展开。

## 五、四道工程约束（治理）

如果说两条主线是 ArchGraph 的"身体"，下面四道约束就是它的"纪律"——它们保证图不会腐化、交付可回归、变更可追溯。

1. **定位先行（Intent Architecture First）**
   动手前，先在图里找到（或创建）任务对应的架构元素与视图。元素必须属于至少一个视图，不允许存在"图之外的孤儿元素"。

2. **验收先行（Acceptance Test First）**
   每个元素挂载 GIVEN-WHEN-THEN 格式、**可执行**的验收用例；改动前先识别受影响用例，改动后跑回归。验收从**外部视角**验证元素承诺的行为，而不是验证内部实现。

3. **变更可证（Traceability）**
   每次提交后，把 **commit id + 文件路径**回登记到对应元素。元素因此拥有自己的"变更时间线"，谁在何时改了什么，一目了然。

4. **写入无害（Dedup + Lossless）**
   写图默认**复用**而非新建：精确重复直接复用，同类型语义近似的新元素会被拦下并要求显式放行。写操作**无损**：省略不等于删除，删减内容要么是合并且不丢失，要么需显式确认；破坏性删除会进入**墓碑账本**以便恢复。

> 这一线将在后续篇章《工程可信与治理》《写入治理：去重、无损与墓碑》中展开。

## 六、系统全景

从一张分层视角看，ArchGraph 连接了六个角色：

| 层 | 角色 | 职责 |
|----|------|------|
| 人 | 人类伙伴 | 定方向、做裁决、观察与纠偏 |
| 执行 | 编程 Agent（各 Harness 中） | 定位元素、武装技能、按约束交付 |
| 接口 | **ARGO MCP** | 读写意图图的**唯一**通道（语义 + 结构） |
| 事实源 | **意图架构图** | 单一事实源，ArchiMate 3.2 建模 |
| 元语言 | **ArchiMate 3.2 + AML** | 元素/关系/视角的合法结构 |
| 互操作 | **Enterprise Architect (.qea)** | 与专业建模工具双向交换 |

配套的 **ARGO 工具链**（规则、技能、Agent 定义、部署器）负责把这套约束**自动部署**到所有主流编程 Harness。

## 七、落地与生态

- **多 Harness 一套源**：一条 `argo-deploy` 把 ARGO MCP、Skills、Rules、Agents 部署到 GitHub Copilot、Cursor、OpenCode、DeepSeek Harness、OpenClaw。一份源文件，多端运行。
- **EA 互操作**：与 Enterprise Architect 双向投影，专业建模工具里的图可以在 ArchGraph 工作流中被读取与回写。
- **知识复用与联邦**：可分享的子图工作包（角色、流程、目标、约束、测试的完整语义网络）可在项目与社区之间导出、复用与组合。更进一步，社区以**联邦**方式协作——每个项目保持自己的图主权，通过注册中心登记、发现、授权，并**按引用**读取彼此开放的子图（register / discover / authorize / read）；访问默认拒绝，不复制、不合并。
- **可观测与成本**：框架内置后台日志，把每次工具调用与其 token 成本写入工作区单一 `agent-cost-log.ndjson`；配套的 `agent-search-diagnosis` 技能可把一次会话转成自包含诊断包，让"过度搜索 / 无效轮次 / 图↔仓往返"可见、可优化。
- **精益读取**：结构读取默认省略账本字段（commit / testcase），语义命中附带 `matchedSnippet` 说明"为何命中"——让 Agent 只在有价值处消耗上下文。
- **内容体系**：本文所属的「框架介绍系列」，加上既有的官宣、创新点、多角色、社区、Skill 共演化、洞察报告等文章，正在**逐步收拢进同一套体系**，以本文为总纲重新组织。

## 九、快速开始

```powershell
npm install -g archgraph-argo
argo-deploy
```

安装后打开项目、启动编程 Agent，它会自动：**先定位**（在图里找到任务背后的架构元素）→ **再武装**（获取该元素关联的 Skill 与 Rule）→ **测试先行**（用 GIVEN-WHEN-THEN 驱动实现）→ **可追溯**（提交并回登记到图谱）。

> 语义（Graph RAG）检索需额外配置 Neo4j 与向量引擎；其余能力开箱即用。
> Embedding 可指向**任意 OpenAI 兼容端点**：沿用云端 profile，或设 `ARGO_EMBEDDING_PROFILE=openai-compatible` 接入自建模型，用于离线/内网/私有化部署（详见 `docs/self-hosted-embedding-deployment.md`）。
