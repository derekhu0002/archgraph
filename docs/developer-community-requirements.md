# ArchGraph 开发者社区 — 需求分析

> 工作包：开发者社区开发交付（2751）
> 角色：产品经理（xiaoniu）
> 交付对象：系统设计师（caoyang）

## 1. 背景与目标

ArchGraph 开发者需要一个场所来交流他们导出的「工作包」。工作包是通过
`eatool/EA-jsscript/export-to-kg.js` 导出的、开发者认为值得与他人分享的知识图谱子图。

本需求的目标：搭建一个「ArchGraph 开发者社区」，让开发者能够**发布、浏览、下载并讨论**工作包，
从而复用彼此的子图，加速 agentic engineering 实践。

非功能约束：**采用 GitHub Discussions 作为社区载体**（零成本、零运维、GitHub 生态内），不自研社区系统。

## 2. 用户场景

| 编号 | 场景 |
| --- | --- |
| S1 | 开发者打开社区（GitHub Discussions），浏览他人分享的工作包帖子列表 |
| S2 | 开发者把本地导出的子图 JSON 以 Gist/仓库文件发布，并在 Discussions 发帖（填写名称、描述与子图链接） |
| S3 | 开发者打开某个工作包帖子详情，查看名称、描述、作者与子图内容 |
| S4 | 开发者通过帖子中的链接获取（下载）某个工作包子图，用于导入自己的项目 |
| S5 | 开发者在工作包帖子下评论/提问，与作者交流 |

## 3. 用户故事

- US-1：作为一个开发者，我想要浏览已分享的工作包帖子列表，以便发现可复用的子图。
- US-2：作为一个开发者，我想要把我的子图发布为工作包帖子，以便其他人可以复用。
- US-3：作为一个开发者，我想要查看工作包帖子详情（名称、描述、作者、子图内容），以便决定是否采用。
- US-4：作为一个开发者，我想要通过帖子链接获取工作包子图，以便将其导入我自己的项目。
- US-5：作为一个开发者，我想要对工作包帖子发表评论，以便与作者交流反馈。

## 4. 验收标准（GIVEN-WHEN-THEN）

- AC-1（浏览）：GIVEN 社区（GitHub Discussions）已启用且至少有 1 个已发布工作包帖子；WHEN 开发者打开讨论区列表；THEN 看到工作包帖子列表，每项展示名称与作者。
- AC-2（发布）：GIVEN 开发者持有 `export-to-kg.js` 导出的子图 JSON；WHEN 其将子图 JSON 以 Gist/仓库文件发布，并在 Discussions 发帖（附名称、描述与子图链接）；THEN 该工作包帖子出现在列表中。
- AC-3（详情）：GIVEN 存在一个工作包帖子；WHEN 开发者打开其详情；THEN 看到名称、描述、作者与子图链接/内容。
- AC-4（下载）：GIVEN 工作包帖子包含子图 JSON 的链接（Gist/仓库文件）；WHEN 开发者访问该链接；THEN 得到可导入的知识图谱子图 JSON（符合 `export-to-kg.js` 导出格式）。
- AC-5（讨论）：GIVEN 存在一个工作包帖子；WHEN 开发者发表评论；THEN 评论出现在该帖子下。

## 5. 非功能需求

- NF-1：采用 GitHub Discussions 作为社区载体（零成本、零运维、GitHub 生态内），不自研社区系统。
- NF-2：工作包以可导入的知识图谱子图（JSON）形式交换，符合 `export-to-kg.js` 的导出格式；子图 JSON 通过 Gist 或仓库文件链接分享。
