# ArchGraph 开发者社区 — 方案设计

> 工作包：开发者社区开发交付（2751）
> 角色：系统设计师（caoyang）
> 输入：需求分析 `docs/developer-community-requirements.md`
> 评审：规划专家 tanwen 通过；系统架构师 laodong「需修改」，本版已按反馈修订（补充发布脱敏与下载格式校验）。

## 1. 设计目标

基于需求，为「ArchGraph 开发者社区」给出可落地的技术方案，约束为：**零成本、零运维、GitHub 生态内**。

## 2. 总体方案

采用 **GitHub Discussions**（在 ArchGraph 仓库启用）作为社区载体，**不自研前端/后端服务**。

### 2.1 架构映射

- `ArchGraph开发者社区`（应用组件 2748）由 `GitHub Discussions`（应用服务 2752）提供支撑；
- 原规划的 `开发者社区WEB前端`（2749）与 `开发者社区后端服务`（2750）**不再自研**（架构变更，移除）。

### 2.2 平台依赖边界与大小分级策略

- **平台锁定**：社区能力整体委托给单一外部供应商（GitHub），存在供应商锁定/单点依赖；GitHub 平台中断时社区不可用。该依赖边界可接受，但需在 2748/2752 描述中显式记录，为将来替换载体保留语义锚点。
- **大小分级策略**：子图工作包默认以公开 Gist 承载；公开 Gist 单文件存在大小上限（约 10MB）。**超过 Gist 单文件上限的工作包子图，改用仓库文件承载**（提交到仓库 `KGlibrary/` 目录），以保证大子图可分发。

## 3. 社区结构设计

### 3.1 分类（Categories）

| 分类 | 用途 |
| --- | --- |
| 工作包分享 | 发布 `export-to-kg.js` 导出的子图工作包 |
| 问答讨论 | 使用/复用问题交流 |
| 公告 | 社区动态 |

### 3.2 工作包帖子模板

每个「工作包分享」帖需包含：

- 标题：`[工作包] <名称>`
- 描述：子图用途简介
- 作者：GitHub 账号
- 子图链接：Gist 或仓库文件（`export-to-kg.js` 导出的 JSON）

## 4. 工作包发布流程

1. 开发者运行 `eatool/EA-jsscript/export-to-kg.js` 导出子图 JSON；
2. **发布前脱敏检查**：按贡献指南 `docs/developer-community-guide.md` 的「发布前脱敏检查清单」逐项核对，清理敏感信息（可选发布辅助脚本内置敏感信息扫描与告警）；
3. 将脱敏后的子图 JSON 发布为 GitHub Gist（**超过 Gist 单文件约 10MB 上限时，改为提交仓库 `KGlibrary/` 目录**）；
4. 在 Discussions「工作包分享」分类按模板发帖，附子图链接。

## 5. 发布安全控制（脱敏）

`export-to-kg.js` 导出的子图 JSON 是知识图谱快照，可能携带**敏感信息**：元素属性中的密钥/token、内部绝对路径、commit 详情、个人或组织信息。通过公开 Gist / 仓库文件分享即等于公开泄露，故发布前必须脱敏。

- **必做**：开发者按「发布前脱敏检查清单」（见贡献指南 `docs/developer-community-guide.md`）逐项核对并清理敏感信息。
- **辅助**：可选发布辅助脚本在导出子图后内置**敏感信息扫描**（匹配密钥/token、内部绝对路径、commit 详情、个人信息等模式），命中即告警，开发者须清理后方可发布。

## 6. 下载与导入前置校验

为避免导入恶意/损坏数据，明确 AC-4 的导入前置条件：从帖子链接获取的子图 JSON **须通过 `export-to-kg.js` 导出格式校验**（结构符合 `elements`/`relationships`/`views` 导出格式）**且不超过大小上限**，校验不通过则拒绝导入。

## 7. 验收映射

| 验收 | 实现方式 |
| --- | --- |
| AC-1 浏览 | Discussions 讨论区列表 |
| AC-2 发布 | 发帖 + Gist/仓库文件链接（发布前脱敏检查） |
| AC-3 详情 | 帖子详情 |
| AC-4 下载 | 通过 Gist/仓库链接获取子图 JSON；导入前通过 `export-to-kg.js` 导出格式校验与大小上限校验，不通过则拒绝 |
| AC-5 讨论 | 帖子回复 |
| AC-6 发布脱敏（新增，安全） | 发布前按脱敏检查清单清理敏感信息，辅助脚本内置敏感信息扫描与告警 |

> AC-6 为安全验收意图（对应系统架构师 laodong 建议 4），在需求侧补充安全验收用例，使安全控制可外部验证。

## 8. 交付物清单

1. 启用 ArchGraph 仓库 GitHub Discussions 并配置分类；
2. 工作包帖子模板（贡献指南文档 `docs/developer-community-guide.md`，含「发布前脱敏检查清单」）；
3. （可选）发布辅助脚本：导出子图后生成帖子模板，并内置敏感信息扫描与告警。

## 9. 架构变更

- 新增 `GitHub Discussions`（Application Service），`Serving` `ArchGraph开发者社区`（2748）；
- 移除自研组件 `开发者社区WEB前端`（2749）、`开发者社区后端服务`（2750）及关系 1964。
