研究稿 · 内部
面向 Agent 工程的一张意图架构图：
写入治理、检索优化与可信记忆的实证研究
项目组 · 2026 年 9 月
摘要

面向真实项目工作的 Agent 常出现目标漂移、过程不可观测、验收缺乏依据、经验无法跨会话累积等问题。我们认为这些问题的共同根源，是 Agent 缺少一份可信、可执行、可追溯的项目上下文。既有做法各有侧重：检索增强生成（RAG）擅长按语义召回，但返回的是缺乏结构与依据的片段；把上下文塞入超长提示词可解一时之需，却无法沉淀与复用。本文以一张意图架构图（Intent Architecture Graph）作为项目的唯一事实源，令其同时充当 Agent 的记忆与团队的设计蓝图，并围绕它给出三部分机制：写入治理（复用式去重、无损合并、墓碑账本）、读取优化（子图限定、三层记忆、两步回忆、阈值标定、混合检索与二次重排）与可回归的度量（recall@1/@5、MRR 等）。在仓库内可执行的评测上，向量检索基线的 top-1 召回为 94.6%，top-5 为 99.4%，MRR 为 0.967；在 150 个查询上引入混合检索与二次重排后，top-1 升至 99.3%。本文把这些指标全部固化为可执行用例，使结果可复现、可回归。需要说明的是，本文的评测规模仍然有限，与公开基准不构成同分布比较。

1　引言

让 Agent 承担真实项目工作时，问题往往不在于单点能力，而在于它没有一份「可信的项目上下文」。这种缺失会引出四类可观察的失败：长任务中目标逐步漂移，人却难以及时察觉；过程不透明，Agent 读了什么、依据什么做决定难以追溯；验收依赖主观判断，缺少可执行的标准；一次会话积累的经验无法跨会话、跨人延续。

已有的两类做法都只能缓解其中一部分。以检索增强生成（RAG）为代表的方案[1]长于「按语义找」，但返回的是孤立片段，缺少结构、关系与出处，难以支撑「为什么会这样」这类追问。另一类做法是把尽可能多的资料塞进超长提示词，这能解一时之需，代价是上下文一经更替便无从复用，也无法作为团队的共享资产。

本文的做法是：为每个项目维护一张意图架构图，作为该项目唯一的、可执行的、可追溯的事实源；让这张图既作为 Agent 的长期记忆，又作为人和 Agent 共同的设计蓝图。我们不把「图」当作一次性检索的索引，而是把它当作会被长期写入、必须治理、需要被精确读取的一等工程对象。围绕这一前提，本文给出三部分机制——写入治理、读取优化、可回归度量——并用仓库内可执行的评测加以检验。

本文的贡献可归纳为四点，每点都对应可检验的结果：

C1写入治理：复用式去重、无损合并与墓碑账本三道门禁，使图在长期写入下不因重复或误删而腐化（§3.2）。
C2读取优化：子图限定、三层记忆、两步回忆、阈值标定、混合检索与二次重排的组合，在节省上下文的同时维持召回（§3.3）。
C3量化评测：以 recall@1/@5、MRR 等标准指标给出检索与记忆的实测结果，并说明其与公开基准的关系（§4、§5）。
C4可回归交付：全部指标固化为可执行用例，使质量可被持续守住（§3.4、§5.6）。

本文的结论受限于单一项目图谱与有限的评测规模，这一点在 §6 中如实讨论。

2　相关工作

检索增强生成。RAG 用检索到的外部文本增强生成质量，显著缓解了模型的知识时效问题[1]。其检索后端以稠密向量为主，常辅以 BM25 等词法通道并做融合[5]。这类方法提升的是「找到相关文本」的概率，其上下文仍是彼此独立的片段，不承诺元素之间的一致性与可追溯性。

图增强检索。GraphRAG 从语料中抽取实体—关系图，并借助社区摘要回答全局性问题，在全局问答上取得了明显优于朴素向量检索的裁判胜率，同时把检索所需的 token 显著降低[2]。LightRAG 进一步以更轻量的图索引改进了效率与质量[3]。这类方法的图是「从文本中抽取」出来的派生产物，而非由人和 Agent 共同维护、并作为施工依据的原始事实源；写入治理与跨会话的长期一致性通常不在其讨论范围。

Agent 长期记忆与基准。Mem0 等系统把对话历史抽取为可检索的记忆，并报告了在准确率与延迟上的收益[4]；LongMemEval[6]、LoCoMo[7] 与 BEAM 等基准则从信息抽取、多会话与时间推理、生产规模检索等维度衡量记忆系统的读写质量。这些工作关注的是「用户—助手」式记忆，其指标口径（LLM 裁判、F1、pass rate）彼此不同，横向比较需格外谨慎。

企业架构建模。ArchiMate 3.2[8] 为系统结构、职责与意图提供了标准化的元素与关系，是业界成熟的公共语言。本文沿用其类型体系作为人机共同语言，并在此基础上补充可执行、可治理的读写机制。综合来看，既有工作分别解决了「找得到」「抽得出」「记得住」的某一面，但尚未把结构、治理、检索与度量放到同一个长期维护的事实源上统一处理。

3　方法
3.1　意图架构图：单一事实源

每个项目维护一张意图架构图，其中元素（人、角色、工作包、技能、规则、组件等）与关系（指派、触发、关联等）都具有类型，并受关系合法性的约束；视图是视角（Viewpoint）在图上的一种投影，用于约束成员与呈现层次。元素上可挂载可执行的验收用例。这张图同时承担两种角色：作为记忆，它保存对话中形成的共识与决策；作为设计蓝图，它承载职责划分、设计取舍与验收标准。人和 Agent 面对同一张图，人看全局，Agent 看与当前任务相关的局部，对齐因此成为结构性的而非会话性的。

3.2　写入治理：三道门禁

图会被长期、多人、多 Agent 地写入，若不治理会迅速膨胀甚至自相矛盾。我们让所有写入经过同一通道，并依次通过三道门禁。

门禁 机制
去重写入默认「复用」：类型与名称均相同的对象直接复用；同类型且语义近似的新对象会被软门禁拦下并给出候选，须显式放行并说明理由方可创建。
无损写入不静默丢内容：结构化字段按名称合并，标量文本受保护，「省略不等于删除」；确需删减时必须显式确认。
墓碑破坏性删除（元素、关系、视图）被记入可恢复的墓碑账本，完整对象留痕，可回溯、可恢复。
3.3　读取优化：省上下文与提性能

读取的目标是「取得到、取得准、且尽量少占上下文」。我们使用五种手段：其一，把检索限定在某张视图或某个元素子树之内，避免全图铺开；其二，按人类记忆的层次组织记忆——工作记忆在会话开始时只加载一份紧凑摘要，长期记忆命中才召回，档案只在显式检索时读取；其三，两步回忆，先以紧凑卡片定位，再按需取全文；其四，对语义检索的种子做阈值标定，滤除无关内容；其五，向量语义与词法 token 双通道融合，再由 LLM 对候选做一次精排，失败时回退原序而不阻塞。多通道并发执行以缩短时延，检索所用的向量投影也做了瘦身以控制大图下的内存占用。

一条贯穿性约束：上述优化不得以牺牲检出率与召回率为代价——宁可多消耗计算，也不通过缩小候选池、截断内容或跳过重排来换取速度。该约束同样约束 §5 中的所有取舍。
3.4　度量与可回归交付

我们把「检索那一步」拆成标准指标：recall@1 与 recall@5 衡量前 1 / 前 5 是否命中，MRR 衡量首个正确结果的排位质量，Precision 与 HitRate@K 衡量准确性与命中率。每个元素的验收用例以 GIVEN-WHEN-THEN 写成可执行形式，每次提交后把 commit 与文件路径回登记到对应元素。这样，图不仅是知识，也是可被机器执行的度量与追溯载体。

本节说明我们在什么数据、什么口径下、与哪些基线比较。

5　结果与对比
5.1　检索质量与消融

在 150 条查询的四路对比中，向量基线 top-1 召回为 95.3%，top-5 为 100%；混合检索把 top-1 抬到 96.0%，提升有限；仅对向量通道做重排反而降到 92.7%，而混合检索叠加二次重排后达到 99.3%，MRR 为 0.997（图 1）。这一组结果说明两点：其一，当基线已经较高时，单看 top-1 的绝对提升空间本就有限；其二，重排并非独立有效，它与混合检索的候选质量相互依赖——仅向量重排的下降提示，重排器对候选集的质量敏感。

5.2　分对象差异

按查询对象分解向量基线（图 2）：关系类查询的 top-1 召回为 100%，描述类为 98.4%，视图类为 98%，整体为 94.6%，而名称类仅为 92.0%，是主要短板。名称类多为简短的专有名词或代号，与上下文的语义信号弱，这与向量检索「重语义、轻字面」的已知特性一致，也提示词法通道在名称类上更有价值。

5.3　语义阈值标定

读路径的种子阈值需要权衡：过低会把无关内容一并召回，过高则会误伤相关项。我们在 24 条无关探针与 8 条相关目标上测量相似度分布，发现两类几乎可分——无关样本的上界为 0.686，相关样本的下界为 0.833（图 3）。取窗口内的 0.70 后，无关命中降为 0，而相关召回保持 8/8 不降。需要提醒的是，该阈值与所用 embedding 模型绑定，更换模型后必须重新标定。

5.4　记忆任务

在 31 条记忆任务上，整体正确率为 100%，拒答准确率为 100%，平均时延约 5.7 ms（图 4）。这些数字来自本仓库自建的、与项目场景绑定的题集，规模有限，不宜与公开基准直接比较；其价值在于可随每次改动自动回归，防止退化。

5.6　代价与默认配置

二次重排虽把 top-1 抬到最高，但它对提示与模型敏感、在小样本上噪声较大，因此默认关闭，按场景开启（表 3）。这与本文的召回优先约束并不矛盾：候选池始终不缩小，只是在默认路径上省去一次精排的时延与成本。此外必须指出，写入治理的三道门禁目前只有机制性保证（如复用式去重使精确重复不再新增），尚缺乏「治理前后腐化程度」的对照量化——这是我们下一阶段要补的实验。

6　讨论与局限

我们在一张长期维护的意图架构图上，把写入治理、读取优化与可回归度量整合为一套机制，并给出在仓库内可复现的检索与记忆结果。就我们所知，把「图即记忆、图即设计蓝图」「写入三道门禁」「在召回优先约束下的读优化与度量回归」放到同一个事实源上处理，是本文工作的主要特点。

但结论的适用范围有明确边界，以下威胁需要正视：

局限 说明
单一项目图谱评测只在一个项目的图上进行，跨项目、组织级联邦的效果尚未验证，结论不宜外推。
样本规模有限四路对比为 150 条、重排对比更小、记忆题集 31 条；小样本对重排等敏感结论的影响不容忽视。
外部对照非同分布与 LongMemEval、LoCoMo、GraphRAG 等的数值口径不同，表 2 仅供参考，不能作为优劣判定。
写入治理缺对照C1 目前只有机制性保证，尚无「开/关门禁」的量化对照来证明其对召回或腐化的影响。
配置与宣称的落差本文最高结果（99.3%）并非默认配置；默认路径关闭重排，实际部署性能需以默认配置为准看待。
7　结论与展望

本文把「让 Agent 有图可依」从一句设想，落为一组可度量、可回归的工程机制：写入有门禁，读取有优化，检索有指标，交付有回归。在仓库内的评测上，三者都给出了一致的、可复现的结果。我们不主张这些结果优于既有基准，而是主张这套机制使「可信的项目上下文」成为可被持续维护与检验的对象。

下一步工作有三项：在更多项目、更大样本上复测检索与记忆；把「跨项目引用不漂移」纳入正式评测，以支撑「以项目为基本 block」的组织级协作；以及为写入治理补上开/关对照实验，把 C1 的价值从机制声明变为可测证据。
