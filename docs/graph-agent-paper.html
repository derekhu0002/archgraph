研究稿 · 实证研究
面向 Agent 工程的本真图谱：
写入治理、检索优化与可信记忆的实证研究
项目组 · 2026 年 9 月 · 内部研究稿
摘要

面向 Agent 的工程实践中，真正的瓶颈不是「模型能力」，而是 Agent 缺少一份可信、可执行、可追溯的项目上下文；主流方案（向量库 / RAG、超长提示词）在结构、依据与沉淀能力上存在系统性缺口。本文提出以本真图谱（Intent Architecture Graph，唯一事实源、ArchiMate 3.2 建模）为核心的方案，并系统给出三部分机制：写入治理（去重 / 无损 / 墓碑三道门禁）、读取优化（子图限定、三层记忆、两步回忆、语义阈值标定、混合检索与二次重排）、检索指标（recall@1/@5、MRR、Precision/HitRate）。在仓库内可执行评测上，向量检索基线 top-1 召回 94.6%、top-5 99.4%、MRR 0.967；引入二次重排后 top-1 召回提升至 99.3%（最高 100%）；记忆检索正确率 100%、拒答准确率 100%、平均时延约 5.7ms。结果与长期记忆领域的公认基准（LongMemEval / LOCOMO / BEAM）进行了对照。本文的贡献是：把「让 Agent 有图可依」从理念落为一组可度量、可回归的工程机制。

1　引言

让 Agent 承担真实项目工作时，四个问题反复出现：意图漂移（长任务中逐步偏离目标）、黑盒执行（依据与决策不可观测）、验收靠感觉（缺少可执行、可回归的标准）、经验不沉淀（换人换会话即从零开始）。它们的共同根源，是缺少一份人和机器都能读懂、且能被机器执行的项目上下文。

既有做法两侧都不充分：向量库 / RAG 长于「按语义找」，但返回的是零散片段，缺结构、缺关系、缺依据；超长提示词一次性有效，无法沉淀与复用。一句话，二者都没有提供「单一事实源」。

本文的出发点很朴素：给每个项目一张本真图谱，让知识库同时成为 Agent 的记忆系统与设计图纸，使其「有图可依」。围绕这一目标，本文的贡献如下：

C1　写入治理：提出「去重 → 无损 → 墓碑」三道写入门禁，保证图谱在长期写入下不腐化（§3.2）。
C2　读取优化：给出子图限定、三层记忆、两步回忆、阈值标定、混合检索与二次重排的组合方法，在省 Token / 提性能的同时不牺牲召回（§3.3）。
C3　量化评测：以 recall@1/@5、MRR 等标准指标给出检索与记忆的实测基线，并对齐 LongMemEval / LOCOMO / BEAM（§4、§5）。
C4　可回归交付：将全部指标固化为可执行用例，使质量可被持续守住（§5.4）。
2　相关工作
方向 代表工作与差异
检索增强生成（RAG）以向量 / 混合检索增强生成，长于语义召回；但上下文为片段、无结构约束，缺少唯一事实源与写入治理。
图增强检索（GraphRAG）引入图结构提升多跳与全局能力；但多面向「从文本抽取图」，图本身不是人与 Agent 共同维护的工程事实源。
Agent 长期记忆以 LongMemEval / LOCOMO / BEAM 等基准评测记忆读写；本文沿用其指标口径，但把「记忆」与「设计图纸」统一在同一张图上。
企业架构建模以 ArchiMate 3.2 等标准表达系统结构与意图；本文复用之作为公共语言，并扩展出可执行、可治理的读写机制。

与上述工作相比，本文的差异在于：把「结构（图）× 治理（写入门禁）× 检索（读优化）× 度量（指标与回归）」作为一个整体交付，并强调「不牺牲召回」这一硬约束。

3　方法
3.1　本真图谱（单一事实源）

每个项目维护一张本真图谱：元素（人 / 角色 / 工作包 / 技能 / 规则 / 组件…）与关系（指派 / 触发 / 关联…）均有类型、可校验；视图（Viewpoint 的投影）约束成员；元素上挂载可执行验收用例。人和 Agent 面对同一张图——人看全局，Agent 看与任务相关的局部。

3.2　写入治理：三道门禁（C1）
门禁 机制
去重写入默认「复用」：精确重复（类型 + 名称）直接复用；同类型语义近似的新对象被软门禁拦下并给出候选，须显式放行并说明理由。
无损写入不静默丢内容：结构化字段按名称合并；标量文本受保护，「省略 ≠ 删除」；确需删减时必须显式确认。
墓碑破坏性删除（元素 / 关系 / 视图）进入可恢复账本，完整对象留痕，可回溯、可恢复。
3.3　读取优化：省 Token 与提性能（C2）
子图限定：把检索限定在某张视图或某个元素子树，避免全图铺开。
三层记忆：工作记忆（会话开始仅加载紧凑摘要，约 2–4K token）→ 长期记忆（命中才召回）→ 档案；避免全量记忆进上下文。
两步回忆：先语义定位取紧凑卡片，再按需取全文。
语义阈值标定：过滤无关内容，取最大召回点（§5.2）。
混合检索 + 二次重排：向量语义与词法 token 双通道融合，再由 LLM 对候选精排（失败自动回退，不阻塞）。
通道并发与投影瘦身：多通道并发缩短时延；去除大字段的向量投影，修复大图谱内存问题。
硬约束：任何优化都不得牺牲检出率与召回率——宁可多花性能，也不靠「缩小候选池、截断内容、跳过重排」换速度。
4　实验设置
项 设置
数据 / 任务① 检索黄金集（由项目本真图谱自动派生，含名称 / 描述 / 关系 / 视图四类查询）；② 150 样本四路对比集（向量 / 混合 / 重排）；③ 80 样本重排模型对比集；④ 记忆评测题集 31 题（信息抽取 / 多会话推理 / 时间推理 / 知识更新 / 拒答）。
指标recall@1、recall@5、MRR（排序质量）、Precision / Hit Rate@K；记忆侧：正确率、拒答准确率、平均时延。
基线向量检索（topK=8）、混合检索（向量 + BM25 + RRF）、二次重排（LLM listwise）；外部对齐 LongMemEval / LOCOMO / BEAM 头条成绩。
实现检索经统一只读接口；评测 harness 零外部数据库运行时依赖，只读、可复现；所有指标固化为可执行回归。
5　结果与分析
5.1　检索质量

图 1 给出 150 样本四路对比的 top-1 召回。向量基线已达 95.3%（top-5 为 100%）；引入二次重排后 top-1 提升至 99.3%，MRR 达 0.997。单独对向量通道重排反而略降（92.7%），说明重排应与混合检索配合使用。

图 2 按对象类型分解向量基线的召回。关系类查询达 100%、描述类 98.4%；名称类（92.0%）仍是弱项，提示对「精确名」的匹配仍有优化空间。

5.2　语义阈值标定

读路径的种子阈值过低会把无关内容全部召回、过高会误伤相关项。实测（24 条无关探针、8 条相关目标）显示两类的相似度几乎可分：无关上界 0.686、相关下界 0.833（图 3）。取窗口内的 0.70 后，无关命中降为 0，而相关召回保持 8/8 不降。

5.3　记忆评测（对照业界基准）

在 31 题记忆评测上，整体正确率 100%、拒答准确率 100%、平均时延约 5.7ms。图 4 将我们的记忆正确率与长期记忆领域公认基准的头条成绩并列（口径不同，仅供参考：外部为公开基准最好成绩，我们为本仓库可执行题集）。

5.4　消融与默认配置

因向量基线已很高，混合检索的增量有限（top-1 约 +0.4~1.2 点），且二次重排对提示 / 模型敏感、小样本噪声大。故二者默认关闭、按宿主金丝雀开启——在保证召回不降的前提下，把增益留给需要的场景。所有指标均以可执行用例固化，随每次改动自动回归。

6　讨论与局限

价值：本工作把「让 Agent 有图可依」拆成可度量、可回归的工程机制，并在「不牺牲召回」的约束下取得可复现的检索与记忆结果。

效度威胁与局限（如实说明）：

· 检索与记忆评测目前主要在单一项目图谱上进行，跨项目 / 组织级联邦的评测尚待补齐；
· 部分对比集样本量偏小（80 / 150 样本），重排结论对提示与模型敏感，需更大样本与更多模型复核；
· 与外部基准的口径不同（题集、场景裁剪不一致），图 4 的数字仅供参照，不构成严格同分布对比；
· 阈值与 embedding 模型绑定，更换模型（如内网自建）须重新标定。
7　结论与展望

本文以本真图谱为单一事实源，给出写入治理、读取优化与量化评测的一体化机制：写有门禁（去重 / 无损 / 墓碑）、读有优化（子图 / 三层记忆 / 两步回忆 / 阈值 / 重排）、检索有指标（recall@1 94.6% → 重排后 99.3%–100%）、记忆有基准（100%，对齐业界基准），并全部固化为可执行回归。

展望：下一步是在更大规模、多项目（以项目为基本 block、组织级联邦）的场景下验证检索与记忆，并把「跨项目引用不漂移」纳入正式评测。
