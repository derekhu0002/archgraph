# AI 的技能，不是拿来就能用

最近 AI 圈里，人人都在往 Agent 里堆 SKILL——那些教 Agent 怎么干活的技能文件。到处是现成的 skill 包、skill 模板、skill 市场，仿佛往配置里一放，Agent 就自动会了。

可我越来越觉得，这事没那么简单。

人在一家公司练出来的手艺，换一家公司照样水土不服。带团队的经验、对客户的理解、公司里那些说不出口的潜规则，都长在你这个人身上，而不是写在一张纸上。

SKILL 也一样。一个技能被真正用起来，从来不是照搬，而是**内化 + 结合自身情况不断优化**的过程。抄来的 skill，顶多是个起点。

这篇就聊聊这件事，顺便说说 ArchGraph 是怎么做的。

![一份技能手册，正化作光点融入 AI 的身体——技能要"长"在身上，而不是塞进脑子](diagrams/skill-coevolution-banner.png)

## 一、先泼盆冷水：skill 堆得越多，Agent 可能越笨

你可能听说过 context rot（上下文腐烂）。Chroma 2025 年做过一个研究，测了 18 个前沿模型，结果出奇一致：**输入越长，表现越差。** 长上下文不是免费的，塞得越满，越接近腐烂。

有个 Skill Graphs 的作者把这事说得更狠：**"你越教，你的 AI Agent 越笨。"** 把一个大 skill 文件整段加载进上下文，等于拿广度换盲目——什么都看了，什么都没看清。

业界的解法也很一致：**渐进披露**。Anthropic 官方的 Agent Skills 就是这么设计的——启动时只预载技能的 name 和描述（大约 100 个 token），Agent 判断这个话题跟自己有关，才去读技能全文，再按需读引用的文件。官方原话：让 Claude 只在需要时才加载信息。

一句话：**大多数知识应该留在磁盘上，只有真正要紧的才进上下文窗口。**

---

## 二、技能不是写出来的，是用出来的

如果说上面说的是"别把技能塞进上下文"，那更关键的一层是：**技能本身是要长出来的。**

Anthropic 的官方指南里专门有一条建议，叫 "Iterate with Claude"：把跑成功的做法和踩过的常见错误，沉淀回 skill 文件本身；跑偏了，就让 Agent 自己回来读一读、自我审视。官方从一开始就没把 skill 当"一次性写好的静态文档"，而是当"要在一轮轮使用里长出来的东西"。

学术圈也在往这个方向走。有一篇叫 AutoSkill 的论文，讲的正是"内化"这件事：LLM Agent 常常无法跨会话积累个性化能力——今天刚学会的招，明天换个会话又不会了。它的思路是从交互经验里自动提炼 skill、维护、复用，支持持续自我进化。**能力不是写进去的，是用出来的、然后被沉淀下来的。**

还有一篇更绝，叫 From History to State：与其反复用长长的 skill prompt 去教，不如把可复用的程序性上下文"内化"进模型权重里，prompt 的 token 直接减少 2-7 倍。教的内容没有消失，只是从"每次都要念一遍的台词"变成了"长在模型里的本能"。

照搬是每次重新念，内化是长在身上。这就是区别。

---

## 三、技能应该"挂"在活上，而不是"灌"进脑里

道理讲完，说点具体的——ArchGraph 是怎么做的。

在 ArchGraph 里，skill 不是一堆躺在系统提示词里的文件，而是**挂载在意图图谱的工作项上**：

- **平时不占注意力。** skill 躺在图谱里，Agent 干活之前根本不加载它——对应渐进披露和"知识留在磁盘上"。
- **干相关活时才"参考"。** Agent 接到任务，先去图谱里定位对应的架构元素，找到挂载的技能，需要时才拉起来看——对应 just-in-time 加载。
- **踩坑就回写。** 干砸了、失败了，把教训总结出来，刷新回技能本身——对应 Iterate with Claude 和"用中迭代"。
- **导出时带走坑。** 技能连同踩过的坑一起导出给别人，换环境、换 Agent 也不丢。

![技能卡片挂在墙上，Agent 只取下当前任务需要的那一张，其余继续挂在墙上](diagrams/skill-coevolution-mount.png)

这个循环走下来，skill 在 ArchGraph 里就不是一份照搬来的文档，而是一个**会跟着 Agent 一起长大的活物**。

---

## 四、一次真实的"踩坑 → 刷新"

说个我们项目里真实发生的例子。

我们给公众号文章配图，引入了一个"媒体艺术家"角色，配了一个调 DashScope 图像接口的 skill。第一版 skill 写得很顺，结果真跑起来就翻车了——PowerShell 传中文 JSON 乱码导致接口 400，图片传微信又因为超过 1MB 被拒。

按照 ArchGraph 的流程，这些坑没有变成"下次再踩一遍"，而是：

1. Agent 把"必须用 UTF-8 字节传中文"写回了 skill；
2. 把"图片要压到 1MB 以内"也写回了 skill；
3. 下次再调用这个 skill，它已经是一个"带避坑经验"的版本了。

![智能体盯着报错屏幕，正把踩坑笔记写回一本微微发光的技能手册](diagrams/skill-coevolution-refine.png)

这就是内化的过程。skill 不是因为一开始写得完美才变好，而是因为**在真实使用里被不断修正**才变好。

---

## 五、把技能连同坑一起带走

我们做「媒体艺术家」这个角色的时候，还把它做成了一份可移植的接口文档——不只写"怎么调接口"，连"哪个模型名不能用、会返回 400""图片超 1MB 会被微信拒"这些坑，一起写进了文档。

将来有别的项目、别的团队要用这个角色，拿到的不是一份干巴巴的说明书，而是一份**带着前人的避坑经验的技能包**。

![一只装着技能的行李箱，旁边附着一叠避坑清单，正要交给下一个人](diagrams/skill-coevolution-export.png)

这件事在业界的语境里叫"跨会话记住"、叫"可复用能力"、叫"经验跟着技能走"。在 ArchGraph 里，它就是每天在发生的工作流：**挂载 → 参考 → 踩坑 → 回写 → 导出**。

---

## 六、说到底

别人家的方向是"渐进披露 + 内化 + 用中迭代"，ArchGraph 把"参考式挂载 + 经验回流 + 带坑导出"做成了一个闭环。

技能不是拿来就能用的。它要挂在你真实的工作上，要在一轮一轮的使用里被打磨，要把踩过的坑带在身上——这才叫技能。

而这，也正是"**Agent 与人类共同进化**"最具体的落脚点。
