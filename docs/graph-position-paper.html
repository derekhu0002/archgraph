您好：

把我们对「以项目为基本 block」这一方向的思考，连同已落地的框架方法与测评结果，整理成这份材料给您好参考。全文分四部分：先讲业界的一个问题，再讲我们的解决方案，然后讲框架细节，最后给出测评与交付。

一、提出问题：业界的一个问题

今天用 Agent 干活，真正卡住的往往不是「模型够不够强」，而是它没有一份可信、可执行、可追溯的「项目上下文」。行业主流做法有两种，都不太够用：

· 把资料塞进向量库 / RAG：能「按意思找」，但找回来的是零散片段，缺结构、缺关系，也说不清依据与来龙去脉；
· 把上下文堆进超长提示词：一次性有效，无法沉淀、无法复用，还会随会话丢失。

结果就是四个老问题：意图漂移（越做越偏，人难察觉）、黑盒执行（读了什么、为什么这么改，说不清）、验收靠感觉（缺少可执行、可回归的标准）、经验不沉淀（换个人、换一次会话又从零开始）。

再往上一层看：组织想「以项目为单位」协作和复用，也缺一个共同底座——每个项目如果各说各话、知识各存各处，项目之间就无法互认、互借、复用。
二、解决方案：我们怎么做

我们的答案是：给每个项目一张「意图架构图谱」，让知识库同时成为 AI 的记忆系统与设计图纸。

意图架构图谱（已实现）　每个项目里有一张唯一事实源的图谱——用企业架构标准建模，元素、关系、视图都有类型、可校验；它承载项目真实的意图与事实，不是一堆散落的文本。
知识库 = 记忆系统 + 设计图纸　它既是 AI 的长期记忆（记得住聊过、定过的事），也是项目的设计图纸（设计决策、职责、验收标准都写在图上）。
人与 AI 基于架构讨论，让 Agent「有图可依」　人看全局、AI 看与任务相关的局部，但面对的是同一张图；目标对齐不再靠反复解释，而是结构化的。
方向：以项目为基本 block　顺着这个底座继续走，组织的基本单元可以从「人」升级为「项目」——项目即国家、组织即联邦：中枢只登记成员与授权，项目之间以「引用」互借能力，而不是把内容合并或拷贝。
坦诚地说，还有硬问题要面对：联邦中枢怎么避免长成「超级图」、项目之间「默认拒绝」会不会造成协作摩擦、引用会不会悬空漂移、以及人在新的组织形态里的位置。这些不回避，但已不属于本文范围，后续单独探讨。
三、框架细节：Graph 与我们的方法

「有图可依」要成立，关键在这张图写得进去、取得出来、而且取得准。下面三小节分别讲写入、读取与指标。

3.1　写入时的门禁机制（让图不腐化）
门禁 做什么
去重门禁写入默认「复用」：完全重复（同类型 + 同名称）直接复用既有对象；同类型的近似新对象会被软门禁拦下并给出候选，须显式放行并说明理由才能创建。复用是默认，重复要解释。
无损门禁写入不静默丢内容：结构化字段按名称合并，标量文本受保护，「省略 ≠ 删除」；确需删减时必须显式确认。
墓碑账本破坏性删除（元素/关系/视图）进入可恢复账本，完整对象留痕，可回溯、可恢复。

效果：图不会因重复或误删而臃肿、腐化，语义召回也就能保持精准。

3.2　读取时优化 Token 与性能的方法
按「子图」限定检索范围　检索可限定在某张视图或某个元素子树内，避免全图铺开、返回过多内容。
三层记忆，按需加载　工作记忆（会话开始只加载紧凑摘要，约 2–4K token）→ 长期记忆（命中才召回）→ 档案；不把全量记忆一次塞进上下文。
两步回忆　先语义定位拿到紧凑卡片，再按需取全文，避免「一上来就拉全文」的 token 浪费。
种子阈值标定（0.70）　过滤掉无关内容（实测无关探针 ≤0.69、相关目标 ≥0.83，取最大召回点 0.70），无关命中降为 0，而相关召回不降。
混合检索 + 重排　向量「按意思找」与词法「按精确 token 找」并行融合；候选集再经一次 LLM 重排，把最相关的顶到最前（失败自动回退，不阻塞）。
通道并发 + 投影瘦身　多通道并发执行缩短时延；向量投影去除大字段，修复大图谱下的内存问题。
一条底线：所有优化都不得牺牲检出率与召回率——宁可多花性能，也不靠「缩小候选池、截断内容、跳过重排」换速度。
3.3　检出率与召回率：指标与我们的努力

我们把「检索那一步」量化成一组标准指标：recall@1 / recall@5（前 1 / 前 5 命中率）、MRR（首个正确结果的排位质量）、Precision / Hit Rate@K（准确率与命中率）。努力都围绕一个目标：把召回与检出顶上去，且不牺牲准确。

方法 实测（仓库内评测）
向量检索基线recall@1 94.6%、recall@5 99.4%、MRR 0.967
混合检索（向量 + 词法）recall@1 约 96%（小幅提升；基线已高，按宿主金丝雀开启）
二次重排（LLM）recall@1 最高 99.3%–100%，recall@5 100%、MRR 0.997（对提示/模型敏感，默认关、调优后启用）
四、测评与交付
4.1　测评方法
对齐业界基准　以长期记忆领域的公认基准（LongMemEval / LOCOMO / BEAM）为标尺，采用「摄入 → 检索 → 评判」（judge LLM 对照标准答案）的公认流水线；头部成绩（约 92%–94%）作为「世界级」的量化参照。
可执行评测集　自建题集覆盖信息抽取、多会话推理、时间推理、知识更新、拒答等维度，每题写成可回放的用例。
剖面评测　不止看一个总分：把指标按「场景 × 仓规模 × 指标」分场景定合格线（结构定位 / 语义定位 / 多跳导航 / 图仓合成 / 拒答 / 写入登记 …）。
对照实验　同题、同模型、同提示，只改一个变量（如是否挂载图谱工具），用对照证明「机制带来的增量」。

4.3　交付与回归

上述测评都固化成可执行用例（检索基线、记忆评测、重排对比等），随每次改动自动回归——所以指标不是一次性的漂亮数字，而是能被持续守住的门线。测试口径与题集都在仓库内，可复现、可复核。

结语

一句话收束：给项目一张「意图架构图谱」，让它同时成为 AI 的记忆与设计图纸——AI 就能有图可依，人也能基于架构与它讨论；而写有门禁、读有优化、检索有指标、交付有回归，才让这件事真正可用于工程。后续我们会在单项目上继续打磨指标，并逐步探索「以项目为基本 block」的组织级协作。
