把「一个项目」当作一个容器，和 Agent 一起把事做好

一封邮件讲清：它是什么、怎么用、用了之后能带来什么

大家好：

最近我们在推进一套新的协作方式——ArchGraph（ARGO 工具链）。它不要求大家先成为 AI 专家，只要求换一个视角看待「项目」和「Agent」。这封邮件想用最短的篇幅，帮大家建立三件事：它是什么、怎么装怎么用、能带来什么价值。后台是怎么构建的、用了哪些技术组件，这里先不展开，重点放在「怎么用好」。

一、核心理念：以「项目」为单元、为容器

这是大家第一次接触时最需要转过来的一个弯：我们不再把 Agent 当成一个「聊天窗口」，而是把它放进一个「项目容器」里。

  • 项目即容器：每个项目自带一张「项目地图」（知识图谱）。你用 OpenCode、Cursor（也支持 Copilot、DeepSeek Harness、OpenClaw）打开这个项目，就像打开一间办公室。
  • 同一张图：你和 Agent 看的是同一张地图——你看全局（目标、角色、职责），Agent 看与当前任务相关的局部。目标对齐不再靠反复开会，而是结构化的。
  • 上下文不丢：换人、换工具、换会话，项目里的这份共识都还在，不会随聊天记录一起消失。

二、基础操作：安装 → 部署 → 前置准备 → 初始化

整体上只需要记住一句：装一次，之后每个新项目只做一次「初始化」。

第 ① 步：安装（一条命令）

npm install -g archgraph-argo

要求本机已安装 Node.js 18 或以上。

第 ② 步：部署（一条命令）

argo-deploy

它会自动把工具链、技能、规则注册到你常用的编程工具里——GitHub Copilot、Cursor、OpenCode、DeepSeek Harness、OpenClaw。这就是「一份源、多端运行」：不同人用不同工具，也能共享同一套工作方法。

第 ③ 步：前置准备（只为开启「语义检索」能力）

其余能力开箱即用，只有「让 Agent 按意思去检索项目知识」这一项需要两项基础准备：

准备项说明
Neo4j 图数据库存放项目地图的结构化投影，供按结构查询使用。用你自己已有或新起的 Neo4j 实例即可。
向量 / 嵌入服务让 Agent「按意思找」能力的基础。支持任意 OpenAI 兼容端点：可沿用云服务，也可在内网自建，面向离线、私有化部署。
配置 ~/.argo/.env把上面的地址与密钥填进去。部署时会引导你填写；已有内容会被保留，之后也可手改再重新部署。
内网友好：我们在内网/离线环境下的自建向量服务有完整部署指引，不需要依赖公网服务也能跑通。

第 ④ 步：初始化工作区（每个新项目一次）

在一个新项目里，让 Agent 执行一次初始化（argo init）。它会自动：建立起始的「项目地图」、完成首次同步、初始化检索能力并做一次自检。从这一刻起，这个项目就有「记忆」了。

三、知识图谱与资产构建：仓库 + 图谱 = 整个资产

用起来之后，你会发现产出不再只是「代码」。Agent 的记忆、以及你和 Agent 协作得出的设计方案，都会被记录进项目的知识图谱。

  • 记忆会沉淀：Agent 的工作记忆、长期记忆与归档，都挂在项目图谱上，可以按需回忆，而不是淹没在聊天记录里。
  • 设计共识会沉淀：谁负责什么、为什么这么设计、验收标准是什么，都写进同一张图，成为可追溯、可交接的项目共识。
  • 资产 = 仓库 + 图谱：代码仓库（代码、文档、测试）与知识图谱合在一起，才是一个项目的完整资产。
为什么这很重要：知识不再锁在某个人脑子里，也不锁在某一次对话里——它属于项目本身，能被人和 Agent 反复取用。

四、业务理解与进化：它越用越懂你

这套方法的妙处在于「可养成」：

  1. 遇到歧义，先聊清楚，别急着动手。把目标和边界跟 Agent 对齐，让它反过来复述理解、提出澄清问题。
  2. 聊到一定程度，再下命令。当它足够了解业务，你就可以直接安排任务，它会沿着已经对齐的地图去执行。
  3. 做错了，反馈一次，它就记住。错误与教训会被写进图谱记忆，下次遇到同类事情不再重犯。
真实的例子：部署过程中踩过的坑（某个工具端口每次不同、某段脚本中文乱码）被记入长期记忆后，后续会话会自动规避同类问题；每次代码提交也会自动把「改了什么」回登记到地图上的对应元素。这类经验一旦沉淀，就不需要每个人重新踩一遍。

五、交互纪律：一句「本次会话结束」很关键

这是唯一一条需要特别养成的习惯，但它决定了「记忆」是否可靠：

  • 会话开始：Agent 会自动恢复上次的工作记忆与会话钩子，你不需要手动交代前情。
  • 工作中：遇到关键决策、踩坑与修复，它会当场把要点记下来，这是最可靠的骨干。
  • 会话结束：请明确告诉它「本次会话结束」。因为它无法感知会话是否真的结束；只有收到这个信号，它才会把这次的关键内容收口写进记忆。
记住这一条就够了：一次汇报/任务告一段落时，加一句「本次会话结束」。这不是客套，是让经验被保存下来的开关。

六、用了之后，能得到什么

起步快
新项目几分钟就能建好「项目地图」，Agent 有据可依，不再「跑偏了也没感觉」。		 交接稳
每个产出都能追溯到地图上的元素和提交记录，评审与接手不用再翻聊天记录。
越用越省
踩过的坑、定过的方案会沉淀成经验，下次自动复用，团队不必重复踩同一遍。		 可规模化
一套方法多端运行，经验还能以「子图」的形式在项目之间复用，形成组织级能力资产。

七、建议的下一步

  1. 确认环境：请平台/IT 侧确认内网是否具备 Node.js、Neo4j 与内网向量服务（离线部署有现成指引）。
  2. 选一个小项目试点：我们一起完整走一遍「安装 → 部署 → 初始化 → 第一个任务」，半小时内就能看到效果。
  3. 跑通后推广：把试点经验固化成团队模板，再扩展到更多项目。
