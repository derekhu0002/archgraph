以项目为中心，让 AI 越用越懂你

这封邮件讲清：它能带来什么、怎么开始用

大家好：

如果我们能让 AI 像一位熟悉你项目的同事那样工作——不用每次从头解释背景，它记得住你们聊过和定过的事，做完还能把经验留给下一位接手的人——每天能少掉多少重复沟通？这封邮件介绍的，就是这样一种做法，大约 5 分钟读完。

一、先说痛点

用 AI 帮忙做事的同学，大概都碰到过这些情况：

  • 聊了半天，它还是不太懂我们的项目和业务，给的东西比较空泛；
  • 每次都得从头把背景讲一遍，像换了个完全不认识的人；
  • 它做的和我们想要的常常差一点，来回改，还说不清到底哪儿偏了；
  • 同一个错误，这次改了，下次它还会犯；
  • 事情做完，经验没留下，换个人上手又得重新趟一遍。
这些问题的共同点：AI 缺少一个「懂你项目」的长期上下文——它记住的往往只是某一次对话，而不是你的项目。

二、再讲愿景

我们想要的，不是一个更会聊天的机器人，而是一个真正懂你项目的伙伴：

  • 不用每次从头解释：一打开就知道这个项目的来龙去脉；
  • 越用越懂你：你说过的业务、讨论过的方案，它会吸收并记住；
  • 能独立行动：了解到位之后，你可以放手让它去做；
  • 经验能留下：踩过的坑、定过的方案会沉淀下来，谁接手都能接着用。

三、我们建议的解决方案

做法很朴素：把「一个项目」当作一个容器，让 AI 在这个容器里边聊边学、越用越懂。

  • 以项目为中心：项目的背景、目标、约定，都归拢在项目自己的「一张图」里；
  • 围着项目交流：你用平时熟悉的工具（比如 OpenCode、Cursor）打开这个项目，就可以和它围绕这个项目聊天、做事；
  • 同一张图：你和它看的是同一张项目地图，不用反复对齐；换人、换电脑、隔一段时间再来，上下文都不会丢。

四、具体来说，这套「图」怎么帮到大家

这里的「图」，指的是每个项目自己的一张知识图谱。它带来的帮助很实在：

  • 它会替你记住：你和它的每一次交流、每一个决定、每一次改动，都会记进项目自己的知识图谱里；
  • 需要时自动取回：下次不用你重复解释，它会自己把这些找回来；
  • 资产 = 代码仓库 + 项目知识图谱：两者合在一起，才是一个项目的完整资产，可追溯、可交接。

4.1　怎么开始用：四步就能跑起来

第 ① 步：安装（一条命令）

npm install -g archgraph-argo

要求电脑上已装好 Node.js 18 或以上。

第 ② 步：部署（一条命令）

argo-deploy

它会自动适配你平时用的工具——Copilot、Cursor、OpenCode、DeepSeek Harness、OpenClaw。也就是说，同一套方法，不管谁用什么工具都能用。

第 ③ 步：前置准备（为了让 AI 能「按意思找信息」）

其余能力装好即用，只有这一项需要 IT 帮忙准备两样东西，然后把地址填进一个配置文件：

  • 图数据库：存放项目地图，供按结构查询。用已有或新起一个实例（例如 Neo4j）即可；
  • 语义检索服务：让 AI 能「按意思找信息」，既能用云端服务，也能在内网自建；
  • 把上面的地址填进 ~/.argo/.env，部署时会引导填写，已有内容会保留。
内网友好：内网 / 离线环境下的自建方案，我们准备了完整的部署指引，不依赖公网也能跑通。

第 ④ 步：初始化（每个新项目一次）

在一个新项目里，让它执行一次初始化（argo init）。它会自动建好这个项目的「地图」并做一次自检。从这一刻起，这个项目就有记忆了。

4.2　用起来的一个小习惯：会话结束时说一声

这套方法的核心是「越用越懂你」，用起来也很简单：

  1. 遇到说不清、有歧义的地方，先聊清楚，别急着让它动手。把目标和边界讲明白，让它反过来复述一下、向你确认；
  2. 聊到一定程度，再让它去做。它足够了解业务之后，你就可以直接安排任务；
  3. 做错了，指出来一次，它就记住。下次遇到同类事情不再犯。
一个真实的小例子：部署时踩过的坑（某个工具的端口每次不一样、某段脚本中文会乱码）被记下来之后，后续会自动避开同类问题；每次改动也会自动留下记录，其他人就不用重新踩一遍。
就这一条小习惯：一次交流告一段落时，加一句「本次会话结束」。这不是客套，而是让它把这一轮沉淀下来的开关——它没法自己判断会话有没有结束。

4.3　你能得到的价值

  • 起步快：新项目几分钟就能建好「项目地图」，AI 有据可依，不再「跑偏了也没感觉」；
  • 交接稳：每个产出都能追溯到地图上的记录，评审与接手不用再翻聊天记录；
  • 越用越省：踩过的坑、定过的方案会沉淀成经验，下次自动复用，团队不必重复踩同一遍；
  • 可规模化：一套方法多端可用，经验还能在项目之间复用，慢慢积累成团队的能力资产。

4.4　建议的下一步

  1. 确认环境：请平台 / IT 侧确认内网是否具备 Node.js，以及一个图数据库和一个语义检索服务（离线部署有现成指引）；
  2. 选一个小项目试点：我们一起完整走一遍「安装 → 部署 → 初始化 → 第一个任务」，半小时内就能看到效果；
  3. 跑通后再推广：把试点经验固化成团队模板，再扩展到更多项目。
