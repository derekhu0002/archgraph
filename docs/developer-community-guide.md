# ArchGraph 开发者社区 — 贡献指南（工作包发布）

> 面向开发者：如何把自己的知识图谱子图（工作包）发布到 ArchGraph 开发者社区，供他人浏览、下载与复用。

## 1. 工作包帖子模板

在 GitHub Discussions「工作包分享」分类新建帖子，按以下模板填写：

```text
标题：[工作包] <名称>

描述：<子图用途简介，说明它解决什么问题、可复用的场景>

作者：<你的 GitHub 账号>

子图链接：<Gist 或仓库文件链接，指向 export-to-kg.js 导出的 JSON>
```

## 2. 发布前脱敏检查清单

`export-to-kg.js` 导出的子图 JSON 是知识图谱快照，可能携带敏感信息。发布前**必须逐项核对**并清理以下敏感项：

- [ ] **密钥 / token / 密码**：删除元素属性中任何 API key、token、密码、连接串等凭据类信息；
- [ ] **内部绝对路径**：删除或替换为相对/占位路径，避免暴露本机或内网目录结构（如 `C:\`、`\\server\`、`/home/` 等绝对路径）；
- [ ] **commit 详情**：删除与内部代码仓库 commit id、分支、提交记录等敏感标识；
- [ ] **个人信息**：删除邮箱、手机号、员工编号、组织内部分级等个人或组织敏感信息；
- [ ] **内部备注**：删除元素描述/备注中含内部术语、未公开产品规划等不宜公开的内容。

> 可选：使用发布辅助脚本内置的敏感信息扫描，命中敏感模式会告警；清理告警项后再发布。

## 3. 工作包发布流程

1. **导出**：运行 `eatool/EA-jsscript/export-to-kg.js` 导出子图 JSON；
2. **脱敏检查**：按上文「发布前脱敏检查清单」逐项核对，清理敏感信息；
3. **发布文件**：
   - 常规：将脱敏后的子图 JSON 发布为公开 GitHub Gist；
   - 超限：若文件超过 Gist 单文件上限（约 10MB），改为提交到仓库 `KGlibrary/` 目录；
4. **发帖**：在 Discussions「工作包分享」分类按模板发帖，附子图链接。

## 4. 下载与导入前置校验

下载他人工作包子图用于导入时，子图 JSON **须满足**：

- **格式校验**：符合 `export-to-kg.js` 的导出格式（含 `elements` / `relationships` / `views` 结构）；
- **大小上限**：不超过约定的大小上限（超过 Gist 单文件约 10MB 上限的工作包应由仓库文件承载）。

不满足以上前置条件的子图 JSON 应被拒绝导入，避免导入恶意或损坏数据。
