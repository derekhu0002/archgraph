# AGENT 长期记忆系统评测基线调研结论

> 依据：LongMemEval（ICLR 2025, arXiv:2410.10813）、LOCOMO、BEAM，以及 Mem0 开源的评测框架 `mem0ai/memory-benchmarks`（2026 核实）。
> 目的：为「打造世界级最优秀的 AGENT 长期记忆系统」这一总纲提供**业界公认的量化基线**，回答「世界级到底是多少」。

---

## 1. 背景与定位

- 项目愿景 = 为 AGENT 提供长期记忆系统；总纲 = 打造**世界级最优秀**的 AGENT 长期记忆系统。
- 「世界级」不能靠感觉，必须有可对标的量化基线。业界在长期记忆评测上已有公认基准与开源评测套件，本文整理其口径，作为我们的基线依据。
- 与 `docs/terminal-bench-eval-guide.md`（Terminal-Bench 能力基准）互补：Terminal-Bench 测「记忆系统带来的**能力提升**」，本基准测「记忆系统**本身的读写质量**」。

---

## 2. 三大业界公认的记忆基准

| 基准 | 出处/规模 | 测的能力维度 | 当前头部成绩（Mem0 平台） |
|---|---|---|---|
| **LongMemEval** | ICLR 2025，500 题 | 信息抽取、多会话推理、时间推理、知识更新、拒答（abstention） | 94.4%（472/500） |
| **LOCOMO** | 10 段多会话对话，~300 题 | 事实回忆、时间推理、多跳推理 | 92.5%（1425/1540） |
| **BEAM** | 100 对话/规模桶（100K–10M tokens），2000+ 题 | 真实场景记忆检索，10 种记忆能力 | 1M：70.1% pass / 10M：50.5% pass |

要点：
- **LongMemEval** 能力最全面（含「拒答」——记忆里没有就不该硬答），是 5 大能力维度的行业标尺。
- **LOCOMO** 测「长对话中的时间/多跳推理」，规模小、跑得快，适合快速迭代。
- **BEAM** 测「生产规模」（100K–10M tokens）下的检索，是规模化的试金石。
- 论文关键发现：现有商业助手 + 长上下文 LLM 在跨会话记忆上**掉点 ~30%**——这正是长期记忆系统的价值空间。

## 3. 公认评测流水线与核心指标

```
Ingest（摄入） → Search（检索） → Evaluate（评判）
```

- **Ingest**：会话分块 → 抽取事实 → 嵌入 → 建实体关联。
- **Search**：语义相似度 + BM25 关键词 + 实体增强融合打分，`top-k` 检索（常用 cutoff：10/20/50/200）。
- **Evaluate**：LLM 基于检索到的记忆生成答案，**judge LLM** 对照 ground truth 打分。

**核心指标**（可直接作为基线）：
- **准确率 / 记忆召回率**：judge LLM 判定答案与 ground truth 的一致性。
- **检索深度**：不同 top-k（10/20/50/200）下的表现曲线。
- **token 成本**：单次记忆读写消耗的 token（如 Mem0 新算法每次检索 ~7K tokens）。
- **时延**：单次检索/召回耗时（如 Mem0 ~0.88–1.09s）。
- BEAM 另用 **Pass Rate + Avg Score**。

**对齐愿景**：准确率/召回/top-k/时延 直测「**读**的极致」；token 成本与摄入保真度关联「**写**的极致」；结构与索引是手段。

---

## 4. RAG 底层检索指标（行业标准，喂给上面）

- **Precision / Recall**：检索结果中相关记忆的占比与召回比例。
- **MRR**（Mean Reciprocal Rank）：首个相关记忆排位的倒数均值。
- **Hit Rate@K**：前 K 个结果中命中相关记忆的概率。
- **nDCG**：按相关度加权的排序质量。

用途：精确定位「检索那一步」的瓶颈（是召回不够，还是排序不准），比只看端到端准确率更可诊断。

## 5. 对 ArchGraph 的意义（复用策略）

这几个基准默认「向量库 + 事实抽取」后端，但**题目集、能力维度、judge 流程是通用的**。复用方案：

1. **借题不借后端**：采用 LongMemEval 的 500 题 + 5 能力维度（可裁剪适配「agent 工作/元记忆」场景），把我们的检索路径（ARGO 语义查询 `getSystemArchitecture` / `queryNeo4jGraph`）接进去当 Search 阶段。
2. **摄入阶段换成我们的 LTM**：意图图 + 分层 SUBVIEW 即「已结构化记忆」，顺带测「写」的保真度（结构化正确率、会话归纳保真度）。
3. **叠加 RAG 底层指标**：MRR / Hit Rate@K 定位检索瓶颈。
4. **诚实边界**：ArchGraph 是 agent 的元记忆，不是「用户-助手闲聊记忆」，题集需裁剪；但方法论与指标口径可完整复用。

---

## 6. 结论与建议

- 业界公认基线已存在且开源：**LongMemEval（能力最全）+ LOCOMO（快速迭代）+ BEAM（生产规模）**，配合 **Ingest→Search→Evaluate** 流水线与 **准确率/召回/top-k/token/时延 + RAG 底层指标**。
- 建议落地顺序：
  1. 以 LongMemEval 能力维度为骨架，裁剪出「ArchGraph 记忆评测题集」；
  2. 接上我们的检索路径，跑出**当前实测基线**（先立基线，再谈目标）；
  3. 以「头部成绩 ≈ 92–94%（LongMemEval/LOCOMO）」为「世界级」量化门槛的参照；
  4. 最终把评测跑法固化为可执行验收用例，持续回归。
